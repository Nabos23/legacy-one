## 4. Architecture & Security Issues (severity-ranked)

### 🔴 CRITICAL
- **C1 — Privilege escalation via `POST /auth/users`.** Caller supplies arbitrary `organization_id` **and** `role`; service (`auth/services.py:99`) never validates them against the admin's org/role. Any org-admin can create a `super_admin` in any org. (`/auth/admin/users` is the correct sibling.) Schema: `auth/schemas.py:13-20`.
- **C2 — Live secrets committed in `.env`** (`OPENAI_API_KEY`, `MONGO_URL` `admin:admin@…`, `LANGCHAIN_API_KEY`, `QDRANT_API_KEY`, Fernet `ENCRYPTION_KEY`, Langfuse keys). `JWT_SECRET_KEY=change-me-in-production` is the live secret and also signs admin cookies + derives the at-rest key. _(Owner decision 2026-06-23: leave untouched for now — rotation + git purge deferred.)_
- **C3 — CORS `allow_origins=["*"]` with `allow_credentials=True`** (`main.py:92`). Invalid + unsafe given cookie-based admin sessions.
- **C4 — `/generate-prompt` is an unauthenticated LLM endpoint.** Unmetered token-burn / cost amplification; only IP rate-limited (spoofable).

### 🟠 HIGH
- **H1 — No frontend route guard.** `proxy.ts` is **never executed** — Next.js only runs `middleware.ts`. No server-side/edge protection; unauthenticated users load the dashboard shell until an API 401 bounces them.
- **H2 — Admin routes not role-gated.** `(dashboard)/admin/*` and `client/*` layouts differ only by a `variant` prop. Pages without a `ROUTE_PERMISSIONS` entry (e.g. `/admin/dashboard`) render for anyone; enforcement relies entirely on backend rejection. (`dashboard-layout.tsx:17-41`.)
- **H3 — OTP leaked.** `OTP_RETURN_IN_RESPONSE` defaults **true** (`config.py:16`) → reset OTP returned in HTTP body and `print()`ed to stdout (`auth/services.py:199`).
- **H4 — Weak rate limiter** (`core/ratelimit.py`): in-memory per-IP (not shared across workers, resets on restart), trusts `X-Forwarded-For` first hop (spoofable), **fails open** on internal error (`ratelimit.py:128`), unbounded `_hits` dict.
- **H5 — Token storage XSS-exposed.** JWT in `localStorage` **and** non-HttpOnly/non-Secure cookie (`lib/auth-cookies.ts:4`). No refresh; 24h token unrevocable (logout no-op).
- **H6 — No global exception handlers, no security headers, no HTTPS enforcement.** Raw 500s/DB errors can leak internals; no HSTS/CSP/X-Frame-Options/X-Content-Type-Options.

### 🟡 MEDIUM
- **M1 — No MongoDB indexes.** `users.email` uniqueness is app-level find-then-insert (TOCTOU race, no unique index); `organization_id`, `thread_id` unindexed → collection scans.
- **M2 — `next.config.mjs` `typescript.ignoreBuildErrors: true`** — type errors silently shipped. (`images.unoptimized: true` too.)
- **M3 — Port/config drift.** FE default `:8001`, docs/Dockerfile `:8000`, docker-compose maps `8001:8001` with `--reload` + full source bind-mount (dev compose as deploy artifact). **Owner decision: canonical port = 8000.**
- **M4 — No API versioning** (`/v1`).
- **M5 — Two `/chat`-prefixed routers** (supervisor + direct-agent).

### 🟢 LOW
- **L1 — Dead code / artifacts:** unused `/auth/signup` FE method; `/auth/me/permissions` "debug" route; root `test.db`, `qa_test_temp.db`, `test_results.json`, `live_direct_flows_results.txt` (~200KB), `memory_dumps/`.
- **L2 — Two duplicated orchestration stacks** (`ai/` LangGraph-Studio vs wired `backend/chat/graph.py`).
- **L3 — Verbose PII logging** of message bodies/history/outputs; `print()` instead of logger in places.
- **L4 — `.env` committed on frontend** (only the localhost URL today, but tracked).
